    Explain it

    1. My app turns a sound wave into binary in three steps: sampling — it measures the wave's height at evenly spaced times; quantization — each height is rounded to the nearest whole level (0 to 2^bits − 1); encoding — each level is written as binary with leading zeros so every sample has the same number of bits, and all the samples are joined into one long binary string.
    2. 6 bits gives more detail. With 2 bits there are only 4 levels (0–3), so heights get rounded far from their true value; with 6 bits there are 64 levels (0–63), so each rounded level is much closer to the real wave height. More bits = smaller rounding error.
    3. Test B has the longest wavelength (171.50 cm) because it has the lowest frequency (200 Hz). Wavelength = 343 ÷ frequency, so wavelength and frequency are inversely proportional — when frequency goes down, wavelength goes up.
    4. The hardest stage was the binary stage (Stage 4), because negative amplitudes produce negative levels, which cannot be written in binary. I fixed it by shifting each height up before rounding — (amplitude + 1) ÷ 2 × (2^bits − 1) — so levels always land between 0 and 2^bits − 1.
